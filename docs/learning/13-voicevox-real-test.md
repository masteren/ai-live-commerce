# 学习笔记 13:在 Mac 上实际跑 VOICEVOX

## 测量结果(VOICEVOX 0.26.1、ずんだもん、本机 CPU)
| 句子长度 | 合成用时 | 语音长度 |
|---|---|---|
| 17 字 | 约 0.9 秒 | 4.3 秒 |
| 34 字 | 约 1.1 秒 | 5.0 秒 |
| 58 字 | 约 2.4 秒 | 12.5 秒 |
| 90 字 | 约 3.7 秒 | 19.1 秒 |
- 合成速度约为「实时的 5 倍」,没有冷启动开销。
- 应用整体:发弹幕 → 收到回答(含语音)约 1.3〜2.2 秒(规则回答时)。同一句话第二次走缓存,0.01 秒。
- 浏览器里确认了:语音从头播到尾、接入了口型分析、播放期间 3D 模型的嘴在动。

## 发现的 bug:改了 `AUDIO_DIR` 语音就 404
- 原因:语音文件存在 `AUDIO_DIR`,但 URL 是按「它在 `app/static` 下面」拼出来的。服务器只对外提供 `app/static`,所以目录一变就找不到。默认值又是相对路径,换个目录启动服务器也会出同样的问题。
- 修正:在 `/static/audio` 上**单独挂载** `AUDIO_DIR`(注册在 `/static` 之前,所以优先匹配);默认值改成绝对路径。
- 教训:**「文件存在哪」和「URL 怎么访问」是两件事**,配置只改了一边就会坏。测试里加了「往 AUDIO_DIR 放一个文件,用 URL 能取到」的检查。

## 现在的流程和它的代价
主播发言 = 等 TTS 合成完 → 再把文字和语音一起广播。所以合成要多久,观众就要多等多久(用 LLM 时约 1.5 秒 + 合成 1〜2.5 秒)。
如果觉得慢,可以考虑:① 先广播文字,合成完再补发语音 ② 启动时预先合成固定台词(自动播报、道谢)。目前还没改。
