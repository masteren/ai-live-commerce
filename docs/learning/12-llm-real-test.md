# 学习笔记 12:第一次用真实的 LLM 跑——提示词管不住的,用代码把关

用真实的 OpenAI key(gpt-4o-mini)向主播提问,一共调了 4 轮。模拟测试全部通过的代码,真实运行后暴露了 4 个问题。

## 发现的问题和对策
| 实际发生的事 | 原因 | 对策 |
|---|---|---|
| 情绪永远是 `normal` | 提示词的输出示例里写死了 `"emotion": "normal"`,模型照抄 | 示例改成占位说明,并写明每种情绪的选择标准 |
| **编造事实**:被问颜色时回答「黒と白の2色」(数据里没有) | 「不清楚就说确认」这种写法太弱 | 明确列出「数据里没写的(颜色、尺寸、重量、保修…)不许回答」 |
| **数字说错**:折扣 38% 说成 36% | 模型自己算了一遍 | **代码校验**:`facts_are_consistent()` 把回答里的金额、折扣率、库存数和 DB 对照,不一致就不用这条回答,改用规则回答 |
| 让观众去看不存在的「公式サイト」 | 提示词禁止了也不听 | **代码处理**:`strip_fake_referrals()` 删掉提到官网/店铺/电话的句子 |
| 靠数字判断的情绪不准(库存 15 件→troubled、折扣 38%→excited) | 模型不擅长阈值判断 | **代码补正**:`adjust_emotion()` 按 DB 的实际数字决定 |

## 学到的原则(面试可以直接讲)
1. **LLM 的输出是「不可信的输入」**,和用户提交的表单一样要校验。格式(JSON)、引用的 ID、数字都要查。
2. **能用代码确定的事,不要交给提示词。** 提示词是「请求」,代码是「保证」。数字是否正确、阈值判断这类事用代码做。
3. **示例会被照抄。** 提示词里的例子是最强的指示,写死的值会原样出现在输出里。
4. **模拟测试证明不了模型的行为。** 它只能证明「我们的代码对某种返回的处理」;模型实际会返回什么,只有真跑才知道。
5. 校验有极限:`facts_are_consistent` 只能发现「不在商品数据里的数字」,如果模型把 A 商品的价格说成 B 商品的价格,发现不了(测试里也写明了这个限制)。

## 测试时踩的坑
- 「花奈さんの声かわいいですね」不是提问,只有 30% 概率被回答 → 测试脚本一直等到超时。验证时把 `CHAT_REPLY_PROB` 设成 1。
- 两次回答之间有最小间隔(4 秒)→ 测量延迟时要扣掉。LLM 本身约 1〜2 秒。

## 自测问题
1. 为什么折扣率要用代码校验,而不是在提示词里写「不要算错」?
2. `facts_are_consistent` 检查哪三类数字?它发现不了什么样的错误?
3. 提示词的输出示例里为什么不能写 `"emotion": "normal"`?
4. 校验不通过时,为什么不把这条回答存进对话历史?
