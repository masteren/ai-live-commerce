# 学习笔记 19:Python 侧的三处优化(连接复用、语音缓存上限、订单分页)

## 1. 复用 HTTP 连接(`app/http_pool.py`)
**原来**:每次调 LLM / VOICEVOX 都写 `async with httpx.AsyncClient() as client:`,用完就关。等于每次都重新建 TCP 连接,HTTPS 还要重新做 TLS 握手。

**现在**:每个外部服务只建一个 `AsyncClient`,一直留着用(`SharedClient`)。httpx 的客户端内部有连接池,第二次请求会直接用上一次的连接。
- 第一次用的时候才创建(import 时还没有事件循环)。
- 被关掉了就重建。
- 服务器关闭时统一关掉(`app/main.py` 的 lifespan 末尾)。不关的话 Python 会警告「有没关的连接」。

**实测**(同一台 Mac,各 6 次,取中位数):
| 目标 | 每次新建 | 复用(第 2 次以后) | 省下 |
|---|---|---|---|
| OpenAI(HTTPS,不带 key 的请求,只返回 401) | 229ms | 165ms | 约 65ms |
| VOICEVOX(本机) | 11ms | 1ms | 约 10ms |

老实说**效果不大**:OpenAI 一次回答本身要 1〜1.5 秒,省下的 65ms 只占 4〜5%。但这是「零成本的正确写法」,而且面试时能讲清楚「连接池」「TLS 握手」是什么。

## 2. 语音缓存有上限(`app/tts.py`)
**原来**:每句不同的话存一个 wav,只增不删。接真实 LLM 长期跑,回答几乎每次都不一样,硬盘会一直被占用。

**现在**:最多 `AUDIO_CACHE_MAX_FILES` 个(默认 500)。超过时,删掉「最后一次被用到的时间」最早的那些 —— 这叫 **LRU**(Least Recently Used)。
- 怎么记录「最后一次被用到」:命中缓存时用 `os.utime` 把文件的修改时间更新成现在。删除时按修改时间排序就行,不需要另外的数据库。
- 效果:固定台词(自动播报、道谢)经常被用到,会一直留着;只说过一次的回答会被淘汰。
- 写文件先写成 `xxx.wav.tmp`,写完再改名(`os.replace`)。改名是原子操作,所以浏览器不会下载到写了一半的文件。
- 文件操作放进 `asyncio.to_thread`,删几百个文件时也不会卡住直播。

## 3. 订单记录加上限(`app/routers/orders.py`)
`GET /api/orders` 原来把这个用户的订单全部取出。现在默认最新 30 条,可以用 `?limit=` 指定(1〜100,超出范围返回 422)。
数据越多越慢的接口,一开始就加上限,是 API 设计的基本习惯。

## 怎么测的
- pytest 新增 3 项:连接复用(两次调用是同一个客户端、关掉后能重建)、LRU(上限 3 时,被用过的旧文件留下、没被用的被删、不留 .tmp)、订单上限。
- 用真的 VOICEVOX、把上限设成 2 跑了一遍:缓存始终是 2 个文件,日志里有「删除了 1 件」;关闭服务器时没有警告。
