# 学习笔记 21:瘦身——删掉「为了已经不存在的东西」而写的代码

先用工具查过:服务器代码约 2350 行,**没有未使用的函数和设置**,JS 也没有没用到的函数,CSS 只有 1 个没用的类。所以不是「到处是死代码」。真正胖的是三类东西:

## 1. 兼容「已经不存在的旧版本」的代码
这些代码当初是必要的(为了不让旧数据、旧 App 坏掉),但现在要兼容的对象已经没有了:

| 删掉的东西 | 当初为什么写 | 为什么现在可以删 |
|---|---|---|
| 旧密码格式 `salt$hash`(12 万次)的验证和升级 | 提高到 60 万次时,老用户还要能登录(笔记 14) | 开发库的 2 个账号登录后已经是新格式;公开服务器是全新的数据库 |
| 「Alembic 导入前的数据库」的接管处理 | 早期用 create_all 建的库,要先标记基准点再迁移(笔记 05) | 那种库已经一个都不剩 |
| `host_reply` 里永远是 null 的 `audio_url` | 改成「先文字后语音」时,照顾还没更新的旧 App(笔记 18) | App 已经更新 |
| iOS 读旧名字 `accessToken` 的 Keychain 迁移 | 改成「按服务器保存登录」时,把旧的搬过去(笔记 17) | 手机上已经搬完 |
| iOS 处理「英文报错数组」 | 服务器改成日文报错之前的格式 | 服务器早就只返回日文一句话 |

**兼容代码是有保质期的**。写的时候就要想好「什么时候可以删」,否则会一直堆积,看代码的人也分不清哪些还在起作用。

保留的:`needs_rehash`(反复次数以后再提高时还要用);所有数据库迁移文件(迁移的历史不能删)。

## 2. 第三方库换成压缩版
three.js 和 three-vrm 原来放的是没压缩的版本,合计 3.4MB → 换成同一版本的 `.min.js`,合计 0.8MB。页面打开时要下载、解析的 JS 少了 3/4。功能完全一样(同一个版本号)。

## 3. 早期方案留下的文件
- 图标的落选方案(剪刀手版、各种表情的对比图)
- 自动生成、容易过时的 `openapi.json`(`/docs` 页面随时能看到最新的 API 文档)
- README 里已经不用的截图

## 顺便整理的结构
`main.py` 从 263 行减到约 180 行:
- 示例商品的数据 → `app/seed.py`
- 输入报错日文化、Content-Security-Policy、安全响应头 → `app/security.py`
`main.py` 只剩「把各部分接起来」(路由、WebSocket、启动和关闭)。

## 结果
| | 之前 | 之后 |
|---|---|---|
| 第三方库 | 3.4MB | 0.8MB |
| `main.py` | 263 行 | 约 180 行 |
| 单元测试 | 125 项 | 123 项(删掉 2 项只测兼容代码的测试) |
