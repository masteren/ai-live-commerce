# 学习笔记 09:去掉「AI 感」——页面设计、商品图片、主播的说话方式

修改前后对比:`docs/images/web_live_before.png`(最初的样子)→ `docs/images/web_live.png`(之后又改成了现在的苹果风格,所以这张已是最新画面)

## 1. 「AI 感」来自哪里,怎么改的
| 原因 | 修改 |
|---|---|
| 渐变、模糊光斑、发光徽章、大圆角+阴影(AI 生成 UI 的固定套路) | 全部去掉。几乎无彩色 + 细线 + 留白;强调色(朱)只用在 LIVE 和折扣上 |
| 商品用 emoji | 加 `products.image_url` 列,自己画的 SVG 插图(`app/static/products/src/`)渲染成 PNG;没有图片的商品仍用 emoji 代替 |
| 主播不管问什么都回 3 句定型文之一 | `app/host_rules.py`:判断「意图」(运费/库存/价格/推荐…)和「哪件商品」(简称也能认:マグ、イヤホン),用 DB 里的真实价格、折扣率、库存回答 |
| 3D 模型头顶被切、打光偏冷 | 镜头拉远、暖色主光 |
| iOS 用 emoji 表情当主播 | 从 Web 的 3D 模型导出 5 种表情的立绘 |

## 2. 技术要点(面试会问)
- **迁移里同时做了「数据迁移」**:加列(结构变更)+ 给已有的示例商品填图片路径(数据变更)。NOT NULL 的列要给 `server_default`,否则已有的行无法满足约束。
- **规则回答写成纯函数**(不访问 DB、不发请求,输入弹幕和商品列表,输出回答)→ 很容易测试(`tests/test_host_rules.py`)。LLM 出故障时也用它兜底。
- **为什么不全靠 LLM?** 成本、延迟、故障。能用规则准确回答的(价格、库存)不必每次问 LLM。
- **设计上的克制**:「不加装饰,用留白和排版」。被问到设计时,可以说明每个取舍:强调色只留一种、圆角统一 4px、不用阴影分层而用细线。

## 3. 这次踩的坑
- iOS 加了立绘后,图片用 `scaledToFill` 把画面撑大,**弹幕列表被挤到高度为 0**——UI 测试报「看不到自己的弹幕」,实际是布局问题。改成 `scaledToFit`,键盘弹出时缩小立绘。
- 登录后「先重连 WebSocket、再发送暂存的弹幕」,偶尔在连接建立前就发送而丢失 → 等连接建立后再发。

## 5. 追记(2026-11-14):改成 Apple Store 风格
作者看了 Apple Store 的页面后要求改成那种风格。只借鉴**设计语言**,不使用对方的标志、图片、文案:
- 浅灰背景(#F5F5F7)+ 白色大圆角卡片(18px)、几乎不用边框
- 很大的粗体标题(「ライブ」64px)配一句副标题
- 顶部一排商品(图片 + 名称 + 价格),点击切换「正在介绍的商品」
- 蓝色胶囊形按钮、蓝色文字链接(末尾带 ›)、毛玻璃效果的导航栏和字幕条
- 系统字体(-apple-system),字距略收紧

实现上只换了 `<style>`、加了标题区和商品横排(`renderStrip()`);JS 的功能逻辑没动,所以全部测试照常通过。
这也是当初把「样式」和「功能」分开写的好处:**换一整套视觉风格,不需要碰业务逻辑。**

## 6. 追记:第二次重做——只换配色不算「那种感觉」
第一次只换了样式表(颜色、圆角、按钮),被指出「在糊弄」。问题在于:一个网站的「感觉」主要来自**页面结构和排版节奏**,而不是配色。
对照参考页面的截图,把结构也重做了:
| 参考页面的特征 | 本页的对应 |
|---|---|
| 一行居中的小字导航 + 右侧图标 | `.nav`(购物袋图标带数量) |
| 导航下的白色通知条 | `.ribbon`(折扣率由商品数据算出,不写死) |
| 左侧特大彩色标题 + 右侧同色标语和蓝色链接 | `.hero` |
| 大图商品横排 | `.strip` |
| 分区标题:前半句彩色、后半句灰色 | `.sec h2`(`<b>` 部分上色) |
| 横向滑动的大卡片货架 + 圆形翻页按钮 | `.shelf` / `.tile` / `.paddles`(scroll-snap) |
| 图标 + 标题 + 说明的白卡片 | `.guide` |
| 注释小字 → 面包屑 → 多列链接 → 版权行的页脚 | `footer` |
| 右下角的圆形头像入口 | `.askbubble`(点了跳到弹幕输入框) |

注意点:
- **只借鉴设计语言**(版式、间距、字号层级、组件形态),不使用对方的标志、图片、文案——这是作品集里必须守的线。
- 页脚的链接全部是真实可用的(页内锚点、打开登录/购物车、/docs、/admin),**不放点了没反应的假链接**。
- 原有元素的 `id` 全部保留,所以功能代码和测试都不用改(浏览器流程测试 17/17 通过)。
