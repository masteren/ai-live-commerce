# 学习笔记 06:CI(GitHub Actions)

## 1. 做了什么
`.github/workflows/ci.yml`:每次 push 到 GitHub(或开 Pull Request)时,GitHub 的服务器自动运行 3 个任务:
| 任务 | 内容 |
|---|---|
| unit-sqlite | Python 3.9 / 3.12 两个版本各跑一遍 pytest |
| unit-mysql | 启动真实的 MySQL 8.4(utf8mb4_bin),用 `TEST_DATABASE_URL` 让同一套 pytest 跑在 MySQL 上 → 验证行锁、迁移、字符集 |
| e2e | 真的启动服务器,跑 test_e2e.py(含 WebSocket) |

本机没装 Docker 也没关系:MySQL 的验证在 GitHub 的服务器上完成。

## 2. 为什么重要(面试会问)
- **防止「我这里能跑」**:在干净的环境里从零安装依赖再测试,能发现漏写进 requirements.txt 的包。
- **防止改坏**:任何改动都自动跑 80 项测试,失败就会在 GitHub 上显示红叉。
- **同一套测试换数据库**:测试代码不写死 SQLite,通过环境变量切换 → 体现「配置与代码分离」(和 .env 是同一个思想)。

## 3. 注意
- 还没有 push 到 GitHub,所以 **CI 还没真正运行过**。第一次运行时,MySQL 上可能会暴露 SQLite 测不出来的问题(比如日期时间的精度、时区格式)——这正是 CI 的价值。
- Python 3.9 已在 2025 年 10 月结束官方支持(EOL),之后建议把本地 venv 升级到 3.12。
