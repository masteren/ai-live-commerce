# 学习笔记 27:AI 主播用评论的语言回复(多言語対応)

## 做了什么
- 以前花奈只说日语。现在观众用中文、英语、韩语等发评论,花奈用**同一种语言**回复文字。
- 日语回复照常有语音。其他语言**只显示文字**,因为 VOICEVOX 只能读日语。
- 自动闲聊、购买感谢、气氛 BOT、页面文字仍然是日语。

改动:`app/ai_host.py`、`app/host_rules.py`,以及 `tests/` 里对应的测试。

## 为什么不是只改一句提示词
提示词里的“必须用日语”删掉后,AI 确实会说外语,但周围的代码都假设“回复是日语”:

| 位置 | 如果不改 | 怎么改 |
|---|---|---|
| 数字校验 `facts_are_consistent` | 只认“円”“在庫…点”,外语回复说错价格也拦不住 | 非日语回复:每个数字都必须存在于商品或店铺信息中 |
| 回复判断 `on_comment` | 外语闲聊可能被当成“不用回答” | 非日语评论一定回答 |
| 备用回复 `rule_reply` | LLM 出错时用日语回答外国观众 | 中文、英文各准备一句说明 |
| 语音 `_speak` | VOICEVOX 读外语会很奇怪 | 只有日语回复才合成语音 |
| 长度上限 `parse_llm_reply` | 英语回复容易被截断 | 字母文字的上限放宽到 4 倍 |

> 面接用:「プロンプトだけに頼らず、LLM の出力をコード側で検証しています。日本語以外の返答では、数字がすべて商品データに存在するかを確認し、一致しなければ返答を使いません。」

## 几个细节
1. **白名单(ホワイトリスト / whitelist)**:外语的单位写法列举不完,所以反过来规定“只有已知的数字才放行”。
2. **白名单的弱点**:`33` 既可能是折扣率,也可能被写成“$33”,数字本身存在就会放行。所以再加了按含义的检查:外币、“7折”、库存件数。
3. **怎么判断“是不是日语”**:不能只看有没有假名,因为英文回复里可能出现日文昵称(`Hi みほさん`)。所以同时看假名比例和中文专用字。
4. **“在庫”不算中文**:只有汉字的短评论按日语处理,中文判定只用日语里基本不用的字(吗、这、们……)。

## 已知的限制
- 用文字写的数字(“五千日元”“five”)校验不到,只能靠提示词要求写阿拉伯数字。
- 编造的联系方式只能拦截日语、中文、英语,其他语言靠提示词。
- 商品名由 LLM 临时翻译,可能译错(实测:gpt-4o-mini 把“不锈钢”译成了“丝袜”)。
- 代码只能发现“混入了日语”,分不清法语和英语,所以法语评论可能收到英语回复。

## 用真实 LLM 测试后又改了什么(gpt-4o-mini,16 条评论)
| 实测发现的问题 | 原因 | 修改 |
|---|---|---|
| 外语评论收到日语回复 | 只在提示词里写了一句通用要求 | 代码判断语言,每条评论都指定 `[返答言語: …]` |
| 耳机折扣 38% 说成 30% | 30% 是别的商品的折扣,校验放行了 | 回复提到某商品时,只和这个商品的数据比较 |
| 折扣 38% 说成 37% | 提示词没给折扣率,LLM 只好自己算 | 把折扣率直接写进商品信息 |
| 重试后还是同样的错 | 重试时没告诉 LLM 错在哪里 | 把校验错误的内容传回给 LLM |

> 面接用:「実際の LLM で検証し、誤りの原因ごとに対策しました。計算が必要な値はプロンプトに渡し、出力はコードで検証して、不合格なら理由を伝えて一度だけ再生成します。」

## 为什么换成 gpt-6-luna
- `gpt-4o-mini` 会在 2027-01-14 停用,早于 2027 年 2 月的展示。
- 同样 16 条评论各测 3 轮:外语回复正确率 gpt-6-luna 42/42,gpt-4o-mini 37/42。
- 代价是响应从约 0.8 秒变成约 2 秒;按 token 用量估算,费用反而略低。

> 面接用:「モデルの変更は感覚で決めず、同じテストケースで正答率・応答時間・費用を比較して判断しました。」
