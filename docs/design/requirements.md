# 要件定義書:AI Live Commerce

**Ver1.0** / 作成:2026年11月 / 種別:就職作品(個人開発)

## 1. プロジェクト概要
### 1-1. 背景
- ライブコマース(配信を見ながら買い物をする形式)は、配信者がコメントに即答して購入を後押しできるのが強みだが、**常に人が配信し続けるのは人件費・時間の負担が大きい**。
- 配信者が答えきれないコメントが流れてしまい、購入につながる質問(在庫・送料・使い方など)を取りこぼす。

### 1-2. 目的
- AI 販売アシスタントが **24時間、コメントに即答できる配信** を実現する。
- 質問への回答から購入までを **1つの画面で完結** させる。
- 価格・在庫など **事実に関わる回答を誤らない**(商品データを根拠にする)。

## 2. 登場人物(ユーザー)
| 種別 | 説明 | できること |
|---|---|---|
| 視聴者(未ログイン) | 配信を見に来た人 | 配信視聴、商品閲覧 |
| 視聴者(ログイン) | 会員登録した人 | 上記 + コメント、カート、購入、注文履歴 |
| 運営者(管理者) | ショップの担当者 | 商品管理、売上統計の確認、BOT の ON/OFF |
| AI ホスト「花奈」 | システム | コメントへの回答、購入へのお礼、無人時の自動トーク |

## 3. 機能要件
### 3-1. Ver1.0 対象機能(スコープイン)
| 機能 | 内容 | 優先度 |
|---|---|---|
| 会員登録・ログイン | ユーザー名+パスワード。Web は Cookie、アプリは Bearer トークン | 高 |
| ライブコメント | WebSocket で全視聴者に即時配信、視聴者数表示 | 高 |
| AI 回答 | 質問は必ず回答、雑談は確率で返答。商品データに基づく回答と感情の出力 | 高 |
| 音声・アバター | 感情に応じた音声合成と 3D アバターの表情・口パク | 中 |
| 商品表示 | 商品カード、商品一覧、AI が話題にした商品を自動で表示 | 高 |
| カート・購入 | カート追加・削除、支払方法選択(モック)、在庫を超える注文の防止 | 高 |
| 購入告知 | 購入をライブで告知し、AI がお礼を言う | 中 |
| 管理画面 | 商品の登録・編集・販売停止、売上統計、BOT 切替 | 中 |

### 3-2. Ver1.0 対象外機能(スコープアウト)
| 機能 | 理由 |
|---|---|
| 実際の決済 | 決済代行サービスとの契約・審査とセキュリティ要件(PCI DSS 等)が必要。Ver1.0 はモック |
| 配送・在庫の外部連携 | 倉庫・配送システムがないため |
| 動画配信(実写) | 本作品は AI アバターによる配信が対象 |
| iOS アプリの 3D アバター | iOS 版(SwiftUI)は実装済み。VRM の 3D 表示は SceneKit/RealityKit 対応が必要なため、Ver1.0 では絵文字の表情で代替 |

## 4. 非機能要件
### 4-1. 性能・可用性
- AI・音声・外部 API が停止しても配信は継続する(定型文・文字のみに縮退)。
- AI の回答は最小間隔を設けてレート制限し、積み残しは最新 3 件まで(古い質問は破棄)。

### 4-2. セキュリティ
- パスワード:PBKDF2-SHA256(60万回)+ ランダムソルト。回数をハッシュに記録し、ログイン時に古い形式を自動更新。
- セッション:HttpOnly / SameSite=Lax Cookie、CSRF トークン、有効期限 7 日(利用のたびに延長するスライディング方式。7 日間まったく使わなければ切れる)、DB にはトークンのハッシュのみ保存。
- ログイン失敗 5 回/5 分でロック、コメント 5 件/10 秒まで。新規登録・管理トークンの誤入力にも回数制限。
- WebSocket 接続時の Origin 検証、画面出力時のエスケープ(XSS 対策)。
- 管理 API は管理者トークンで保護(定数時間比較)。
- 応答ヘッダ(X-Frame-Options: DENY、nosniff)。画面には Content-Security-Policy を付け、自分のサーバのスクリプト以外は実行させない。CORS は既定で無効(同一オリジンのみ)。
- 視聴者のコメントは「引用」として LLM に渡し、コメント内の指示には従わないようプロンプトで指定。LLM の返答はコード側でも検証する。
- DB の CHECK 制約で、在庫・価格が負にならないこと、カート数量が 1〜99 であることを保証。

### 4-3. 運用・保守
- DB 構造は Alembic のマイグレーションで管理。SQLite と MySQL を設定で切替。
- 自動テスト(単体 123 件・E2E 41 件)を GitHub Actions で実行。

### 4-4. 制約
- WebSocket の接続管理・AI キュー・レート制限がメモリ上にあるため **単一プロセスで運用**。複数台に拡張する場合は Redis 等の共有ストアが必要。
